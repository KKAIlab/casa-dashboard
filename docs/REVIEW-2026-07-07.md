## Executive summary

The project is in good overall health. The analysis engine is well factored into
pure, testable modules; t-SNE correctly standardizes features before embedding;
Welch's t-test and its Welch–Satterthwaite degrees of freedom are implemented
correctly; clustering uses a seeded PRNG for reproducibility; and there is no
dangerous DOM injection anywhere (`dangerouslySetInnerHTML`, `eval`, `innerHTML`
all absent). All 54 unit tests pass.

The findings below are ranked by impact. The two highest-value items are
**scientific-correctness** issues in reported metrics (density similarity score,
t-SNE perplexity selection), not crashes — they silently mislead the user. The
rest are maintainability and hygiene items, dominated by a **fully orphaned Python
backend** that duplicates the JS engine and can drift out of sync.

## High-impact findings (methodology / correctness)

### H1. [FIXED] Density "similarity score" had a floor of ~31% and never reached 0

`frontend/src/engine/prediction.js:75-83` (and the mirror in
`backend/core/prediction.py:56-57`).

Jensen–Shannon divergence computed with the **natural log** is bounded to
`[0, ln 2]` ≈ `[0, 0.693]`. The code reports
`similarityScore = (1 - jsDivergence) * 100`, so two **completely disjoint**
distributions score `(1 − 0.693) × 100 ≈ 30.7`, not 0. The full 0–100 range is
never used; every score is compressed into ~31–100 and reads as far more
"similar" than it is.

**Fix:** normalize JSD by `ln 2` before inverting:
`similarity = (1 − jsDivergence / Math.LN2) * 100`. Then identical → 100,
disjoint → 0. (The Python backend squares the scipy JS *distance*, which has the
same `ln 2` ceiling and the same floor bug.)

### H2. [OPEN] t-SNE "best perplexity by KL" systematically prefers the smallest perplexity

`frontend/src/engine/tsne.js:241-252`, described in the README as "Selects best by
KL divergence."

Each candidate perplexity produces a **different** target distribution `P`, so the
achievable KL(P‖Q) is not comparable across perplexities — smaller perplexity
yields a sparser, lower-entropy `P` whose minimum achievable KL is generally
lower. Selecting the run with the minimum KL therefore biases toward the smallest
perplexity in the sweep almost regardless of embedding quality, which defeats the
purpose of sweeping. Consider a perplexity-independent quality proxy (e.g.
trustworthiness / continuity, or a fixed perplexity chosen by `n`), or document
that the sweep is effectively "pick smallest".

### H3. [OPEN] Cluster-proportion classifier confidence is arbitrary

`frontend/src/engine/prediction.js:27-42`. Class probabilities come from a softmax
over **raw, unscaled** Euclidean distances between percentage vectors. The
resulting "probability" has no calibrated meaning — its sharpness depends entirely
on the arbitrary units/scale of the proportion space. It is fine as a nearest-
centroid *label*, but the reported `probability` should be presented as a relative
score, not a confidence. (The backend's Model A uses a real `LogisticRegression`,
so the JS port silently changed the model.)

### H4. [FIXED] No multiple-comparison correction on group comparisons

`frontend/src/engine/exporter.js:44` flags `significant: pValue < 0.05` per
parameter, and the UI runs Welch's t-test across up to 8 CASA parameters
simultaneously. With 8 independent tests the family-wise false-positive rate is
~34%. Consider Holm–Bonferroni or Benjamini–Hochberg, or at minimum a UI note that
p-values are uncorrected.

## Medium-impact findings (maintainability / drift risk)

### M1. [OPEN] The entire FastAPI backend is orphaned dead code

`backend/` (~1000 LoC + its own test suite), `docker-compose.yml`, and
`backend/Dockerfile` are no longer used. Deployment is a **static GitHub Pages
build of `frontend/` only** (`.github/workflows/deploy.yml` builds `frontend/dist`
and never touches `backend/`), and no frontend code calls `/api`, `axios`, or
`localhost:8000` (verified by grep). The backend reimplements the same statistics/
prediction as the JS engine and has already diverged (H3: LogisticRegression vs
nearest-centroid). This is the single largest maintenance liability: it invites
"fix it in the backend" changes that never reach production.

**Recommendation:** either delete `backend/`, `docker-compose.yml`, and the
backend Dockerfile, or move them under an `archive/` path with a README stating
they are not the deployed system. If kept as a reference implementation, add a
test that asserts parity with the JS engine so drift is caught.

### M2. [FIXED] Two unused runtime dependencies shipped in the bundle

`frontend/package.json:15-16` — `axios` and `druidjs` are declared dependencies
but imported nowhere in `src/` (grep-verified). `axios` was the backend HTTP
client; `druidjs` was presumably an earlier t-SNE library replaced by the
self-contained `engine/tsne.js`. Removing them shrinks `node_modules` and the
audit surface (the install currently reports 22 vulnerabilities, several via
transitive deps).

### M3. [FIXED] `npm run lint` failed — 6 ESLint errors

`eslint .` exits non-zero on unused variables:
- `db/index.js:51` — `raw` destructured but unused (though intentional: it strips
  `raw` from the returned list; rename to `_raw` or use `// eslint-disable`).
- `engine/pipeline.js:3` — `standardize` imported but unused.
- `engine/tsne.js:96` — `sum` assigned but never read.
- `hooks/useEngine.js:14` — `data` destructured but unused; `:88` — `step` unused.

None affect runtime (the Vite build doesn't run ESLint), but a failing lint script
erodes its value as a gate. Clean these up and consider adding lint to CI.

### M4. [PARTIAL] `importProcessed` Group/motile-count consistency

`frontend/src/hooks/useEngine.js:41-77`. It stores `group: meta.genotype`
(line 57) rather than `meta.group`, so the Group field entered in the UI for a
processed import is ignored in favor of genotype. It also sets
`motileSperm: data.length` — every imported row is counted as motile, which is
only correct for already-filtered data and inconsistent with the raw-upload path.
Minor, but affects the numbers shown on the Dashboard.

## Low-impact findings (edge cases / polish)

- **L1 — LIN unit inconsistency.** `engine/motility.js:20` normalizes LIN from
  percent to fraction *only inside* `isHyperactivated`. The fertility-axis training
  and co-embedding (`engine/crossSpecies.js`) consume LIN raw. If some datasets
  report LIN as 0–1 and others as 0–100, axis training that pools both conventions
  will produce a meaningless weight for LIN. Per-source standardization masks this
  within co-embedding but not within a single pooled training set. Consider
  normalizing LIN/STR/WOB units once at preprocessing time.

- **L2 — Shift-JIS detection is heuristic.** `engine/preprocessing.js:13-25` decides
  encoding by scanning the first 500 chars for U+FFFD. A UTF-8 file whose garbled
  bytes fall after char 500, or a Shift-JIS file that happens not to produce a
  replacement char early, can be misdetected. Acceptable for the known CASA
  exporters; worth a comment noting the assumption.

- **L3 — `Math.max(...array)` on large arrays.** `engine/prediction.js:48-50` and
  the softmax spread calls use `Math.max(...all.map(...))`. For very large
  embeddings this can hit the argument-count limit and throw. t-SNE is capped well
  below that today, but a reduce-based min/max is safer.

- **L4 — React hooks exhaustive-deps warnings.** Seven `react-hooks/exhaustive-deps`
  warnings across the pages (`db`/`dispatch` omitted from effect deps). Currently
  harmless because those objects are stable, but they are latent bugs if the hook
  identities ever change.

- **L5 — Feature-tuple dedup in the pipeline.** `engine/pipeline.js:22-33` keys
  uniqueness on `VCL_VSL_ALH_BCF` joined as a string. Correct today (duplicates are
  re-expanded on merge-back so proportions are preserved), but note it assumes
  exact float equality; upstream rounding changes could collapse distinct cells.

## What is solid (verified, no action needed)

- **Welch's t-test** (`statistics.js:45-57`) — correct pooled-free SE, correct
  Welch–Satterthwaite df, guards `n < 2` and zero-variance denominators.
- **t-SNE** standardizes inputs (`tsne.js:215`), uses early exaggeration, a
  momentum schedule, adaptive gains, and a seeded PRNG for determinism.
- **K-means** (`clustering.js`) — z-score standardization, `nInit` restarts keeping
  lowest inertia, empty-cluster guard, seeded init.
- **Security surface** — pure static client-side app; no `eval`, no `innerHTML`, no
  network writes, data confined to IndexedDB. CSV is parsed by PapaParse and never
  interpolated into the DOM.
- **Tests** — 54/54 pass, covering config, preprocessing, clustering, t-SNE,
  statistics, motility, exporter, group comparison, cross-species, prediction,
  pipeline, and the IndexedDB layer.
